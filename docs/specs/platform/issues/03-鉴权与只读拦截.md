# 03 钉住鉴权三形态与只读拦截

- 状态：`ready-for-agent`
- Blocked by：02（先有端点测试基建，鉴权用例直接叠加在主缝管道上）
- 缝：REST 主缝 + Dashboard 授权过滤器（REST 断言为主，Dashboard 以过滤器行为补两组）

## 交付什么

安全边界目前同样零护栏：改认证方案、动只读过滤器，CI 不会红。
本票钉住：管理员密钥三种等价携带方式（请求头 / cookie / Basic）、
密钥未配置时的启动告警、只读模式下非 GET 全拦截且 GET 放行。

## 现状

- 鉴权与只读已实现并经发布验证，但行为只有人工记录；
  开发规格 User Stories 11–12 是平台安全边界的承诺，需要测试承载。

## 验收条件

- [ ] 无密钥请求 → 401；三种携带方式（header / cookie / Basic）对同一端点等效放行
- [ ] 错误密钥 → 401，且错误响应不泄露失败原因细节
- [ ] 只读模式开启：POST/PUT/DELETE 全被拦截，错误信息指明只读；GET 正常返回
- [ ] 只读模式关闭：写端点恢复可达（与票 02 用例共用基建）
- [ ] 密钥未配置时启动路径产生告警日志（宿主测试或日志断言）
- [ ] Dashboard 过滤器：无凭据跳转/拒绝，带凭据放行（两组最小断言，不追渲染）

## 不在本票范围

- 多租户、任务级权限（开发规格 Out of Scope）；HTTPS/TLS 配置；密钥轮换策略。
