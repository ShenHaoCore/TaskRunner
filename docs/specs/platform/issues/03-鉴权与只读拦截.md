# 03 钉住鉴权三形态与只读拦截

- 状态：`done`（2026-10-26；后于大众化加固中演进 Cookie 形态，见「后续演进」）
- Blocked by：02（已完成）
- 缝：REST 主缝 + Dashboard 授权过滤器（REST 断言为主，Dashboard 以过滤器行为补最小断言）

## 交付什么

安全边界目前同样零护栏：改认证方案、动只读过滤器，CI 不会红。
本票钉住：管理员三种等价访问方式（请求头 / 登录会话 Cookie / Basic）、
密钥未配置时的启动守卫、只读模式下非 GET 全拦截且 GET 放行。

## 现状

- 鉴权与只读已实现并经发布验证，但行为只有人工记录；
  开发规格 User Stories 11–12 是平台安全边界的承诺，需要测试承载。

## 验收条件

- [x] 无密钥请求 → 401；三种方式对同一端点等效放行：
  - header `X-TaskRunner-Admin` = ApiKey
  - 先 `POST /api/auth/login` 签发 **ASP.NET Cookie 会话票据**（Cookie 名 `TaskRunner.Admin`，**不含密钥明文**），再带 Cookie 访问
  - Basic（任意用户名 + 密钥口令）
- [x] 错误密钥 → 401，且响应不泄露密钥值；登录 Set-Cookie 亦不含密钥明文
- [x] 只读模式开启：POST/PUT 全被拦截（403 + 指明只读），GET 正常返回
- [x] 只读模式关闭：写端点恢复可达
- [x] 密钥未配置时的启动守卫被钉住：生产环境启动即失败（fail-fast，`AdminKeyGuardStartupFilter`——见「偏差修正」）
- [x] Dashboard 过滤器：`/taskrunner` 无凭据 401（`WWW-Authenticate: Basic realm="TaskRunner"`），带凭据 200 渲染

## 偏差修正（本票钉出的真实问题）

1. **REST 鉴权缺口（安全修复）**：`TasksController` 类级无 `[Authorize]`，仅 trigger/pause/resume 三个 action 挂了策略——GET 清单/统计/详情/历史与 **PUT cron（写操作）全部匿名可访问**，违背开发规格 User Story 11。修复：策略上提到类级，删除 action 级重复。对部署方是行为收紧：此前匿名可读的调用方升级后必须携带密钥。
2. **spec 与实现不符**：开发规格写「密钥未配置时启动告警」，实际 Program.cs 是启动抛异常（fail-fast，更严格）。守卫从 Program 下沉为 `AdminKeyGuardStartupFilter`（`AddTaskRunnerAdminAuth` 自动注册，测试可钉），spec 同步修正为 fail-fast。

## 后续演进（大众化加固）

- Cookie 不再存储 ApiKey 明文：`/api/auth/login` 校验密钥后 `SignInAsync` 签发 Cookie Authentication 会话；Handler 只认 Header / Basic；策略同时接受 Cookie scheme 与 ApiKey scheme。
- 契约测试同步：明文 `Cookie: TaskRunner.Admin=<key>` 改为登录拿 Set-Cookie；并断言 Set-Cookie 不含密钥。
