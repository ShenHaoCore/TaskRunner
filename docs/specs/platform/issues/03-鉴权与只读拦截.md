## 验收条件

- [x] 无密钥请求 → 401；三种携带方式（header `X-TaskRunner-Admin` / cookie `TaskRunner.Admin` / Basic 任意用户名+密钥口令）对同一端点等效放行
- [x] 错误密钥 → 401，且响应不泄露密钥值
- [x] 只读模式开启：POST/PUT 全被拦截（403 + 指明只读），GET 正常返回
- [x] 只读模式关闭：写端点恢复可达
- [x] 密钥未配置时的启动守卫被钉住：生产环境启动即失败（fail-fast，`AdminKeyGuardStartupFilter`——见「偏差修正」）
- [x] Dashboard 过滤器：`/taskrunner` 无凭据 401（`WWW-Authenticate: Basic realm="TaskRunner"`），带凭据 200 渲染

## 偏差修正（本票钉出的真实问题）

1. **REST 鉴权缺口（安全修复）**：`TasksController` 类级无 `[Authorize]`，仅 trigger/pause/resume 三个 action 挂了策略——GET 清单/统计/详情/历史与 **PUT cron（写操作）全部匿名可访问**，违背开发规格 User Story 11。修复：策略上提到类级，删除 action 级重复。对部署方是行为收紧：此前匿名可读的调用方升级后必须携带密钥。
2. **spec 与实现不符**：开发规格写「密钥未配置时启动告警」，实际 Program.cs 是启动抛异常（fail-fast，更严格）。守卫从 Program 下沉为 `AdminKeyGuardStartupFilter`（`AddTaskRunnerAdminAuth` 自动注册，测试可钉），spec 同步修正为 fail-fast。
