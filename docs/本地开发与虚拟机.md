# 本地开发 + WSL（Ubuntu）说明书

面向：家里 / 公司 **Windows** 上写代码；**PostgreSQL 与（可选）systemd 服务跑在本机 WSL 的 Ubuntu 里**。

核心原则：**仓库和发布包永远一份；Windows 用 User Secrets，WSL 用 `/etc/default/taskrunner*`，都不要改包内 `appsettings.json`。**

```text
Windows 宿主机                            WSL2 Ubuntu
─────────────────────                     ────────────────────────────
dotnet run Api (Combined)  ──localhost──► PostgreSQL（唯一数据库）
User Secrets → Host=127.0.0.1             库内：业务表 + hangfire schema
publish-linux → tar.gz     ──deploy-wsl──► systemd Api + Worker
                                          /etc/default/taskrunner{,-api,-worker}
                                          Host=127.0.0.1（连本机 PG）
```

WSL2 通常把发行版内监听的端口**镜像到 Windows 的 `127.0.0.1`**，所以开发机连接串一般写 `Host=127.0.0.1;Port=5432`，不必去记会变的 WSL eth0 IP。

---

## 一、WSL：先把 systemd、PG 弄好

### 1. 发行版与 systemd

```powershell
wsl -l -v
# 应看到 Ubuntu（或 Ubuntu-22.04 / 24.04），VERSION 为 2
```

`install.sh` 依赖 **systemd**。在 WSL 里：

```bash
# 写入（若尚无）
grep -q systemd=true /etc/wsl.conf 2>/dev/null || printf '[boot]\nsystemd=true\n' | sudo tee -a /etc/wsl.conf
```

回到 **Windows PowerShell**：

```powershell
wsl --shutdown
wsl -d Ubuntu   # 发行版名按 wsl -l 为准
```

进 WSL 后确认：

```bash
systemctl is-system-running   # 期望 running（degraded 有时也能用）
```

### 2. 安装 PostgreSQL

在 WSL 内：

```bash
sudo apt update
sudo apt install -y postgresql
sudo -u postgres createuser -P taskrunner    # 记住密码
sudo -u postgres createdb -O taskrunner taskrunner
sudo systemctl enable --now postgresql
```

### 3. 让 Windows 能连上（localhost）

```bash
sudo -u postgres psql -c "SHOW config_file;"
sudo -u postgres psql -c "SHOW hba_file;"
```

`postgresql.conf`：

```conf
listen_addresses = '*'
# 或至少 listen_addresses = '0.0.0.0'
```

`pg_hba.conf` 增加（WSL 经 localhost 进来时，常见为本机）：

```text
host    taskrunner    taskrunner    127.0.0.1/32    scram-sha-256
host    taskrunner    taskrunner    ::1/128         scram-sha-256
# 若仍连不上，可临时放宽（仅本机开发）：
# host  all  all  0.0.0.0/0  scram-sha-256
```

```bash
sudo systemctl restart postgresql
ss -lntp | grep 5432
```

在 **Windows** 上测：

```powershell
Test-NetConnection 127.0.0.1 -Port 5432
```

`TcpTestSucceeded` 应为 `True`。若失败：确认 WSL 未 `wsl --shutdown`、PG 在听、Windows 防火墙未拦。

## 二、Windows：第一次准备开发

### 1. 工具

| 工具 | 说明 |
|------|------|
| .NET 9 SDK | `dotnet --version` 为 9.x |
| Git | clone / pull |
| WSL2 + Ubuntu | 上面一节 |

不必在 Windows 再装 PostgreSQL / Docker PG。

### 2. 拉代码并写 Secrets

```powershell
cd E:\Repos\TaskRunner   # 换成你的路径
git switch develop

# PG 在 WSL，走 localhost 镜像（把密码换成你的）
./scripts/setup-dev-secrets.ps1 -VmHost 127.0.0.1 -Password "你的密码"
```

等价写法：

```powershell
./scripts/setup-dev-secrets.ps1 -ConnectionString "Host=127.0.0.1;Port=5432;Database=taskrunner;Username=taskrunner;Password=你的密码;"
```

**不要改** `src/appsettings.json`。家里 / 公司电脑各设一次（Secrets 不跟电脑走）。

### 3. 跑起来

先保证 WSL 开着且 PG `active`，再在 Windows：

```powershell
dotnet test
dotnet run --project src/TaskRunner.Api
```

开发环境 Api 是 **Combined**，一般不必再开 Worker。数据进 **WSL 里那同一个库**。

| 入口 | 地址（Windows 浏览器） |
|------|------------------------|
| 首页 | http://localhost:5088 |
| Dashboard | http://localhost:5088/taskrunner |
| Scalar | http://localhost:5088/scalar |

## 三、把程序也装进 WSL（类生产）

让 Api + Worker 以 systemd 跑在 WSL 里（与 Windows 上 `dotnet run` **不要同时**抢 Hangfire Server）。

```powershell
./scripts/publish-linux.ps1
./scripts/deploy-wsl.ps1
# 发行版名不是 Ubuntu 时：
# ./scripts/deploy-wsl.ps1 -Distro Ubuntu-24.04
```

（也可用 `deploy-ubuntu-vm.ps1`，需在 WSL 里装好 `openssh-server` 并 `ssh 用户@127.0.0.1`；**推荐直接用 `deploy-wsl.ps1`。**）

### 第一次：只改 WSL 里的 env

```powershell
wsl -d Ubuntu
```

```bash
sudo nano /etc/default/taskrunner
# ConnectionStrings__Default='Host=127.0.0.1;Port=5432;Database=taskrunner;Username=taskrunner;Password=你的密码'

sudo nano /etc/default/taskrunner-api
# Hangfire__AdminApiKey='自己想一个足够长的密钥'
```

**不要**改 `/opt/taskrunner/**/appsettings.json`。

```bash
sudo systemctl start taskrunner-api taskrunner-worker
systemctl status taskrunner-api taskrunner-worker
curl -H "X-TaskRunner-Admin: 你的密钥" http://127.0.0.1:5088/api/tasks
```

从 Windows 浏览器访问 WSL 里的 Api：默认服务只绑 `127.0.0.1`，WSL localhost 镜像下可用 `http://127.0.0.1:5088`；若不通，再在 env 里加 `ASPNETCORE_URLS='http://0.0.0.0:5088'` 后重启。

### 开发 Combined 与 WSL Worker 不要同时开

- **日常改代码**：Windows `dotnet run`；WSL 里 `sudo systemctl stop taskrunner-api taskrunner-worker`
- **验 Linux 部署**：停掉 Windows 上的 Api，再在 WSL `systemctl start ...`

## 四、日常怎么用

| 你想做的事 | 在哪 | 怎么做 |
|------------|------|--------|
| 改代码、调试 | Windows | WSL/PG 开着，`dotnet run --project src/TaskRunner.Api`（空库会自动 Migrate） |
| 显式迁库 | Windows | `./scripts/ef-database-update.ps1`（连接串走 Secrets / 环境变量） |
| 换库密码 | Windows | 再跑 `setup-dev-secrets.ps1 -VmHost 127.0.0.1 -Password ...` |
| 验 systemd | Windows → WSL | `publish-linux.ps1` + `deploy-wsl.ps1` |
| 升级 WSL 里程序 | 同上 | 重装；`/etc/default/taskrunner*` 会保留（旧单文件会拆分） |
| 只改服务密钥 | WSL | 编辑 `/etc/default/taskrunner-api`，`systemctl restart taskrunner-api` |

## 五、脚本速查

| 脚本 | 谁用 | 干什么 |
|------|------|--------|
| `setup-dev-secrets.ps1` | Windows | User Secrets（WSL PG → **`127.0.0.1`**） |
| `ef-database-update.ps1` / `.sh` | 宿主机 | 显式 `dotnet ef database update`（可选；启动也会自迁） |
| `publish-linux.ps1` | Windows | 打 linux-x64 包 |
| `deploy-wsl.ps1` | Windows | 把包装进本机 WSL 并 `install.sh` |
| `deploy-ubuntu-vm.ps1` / `.sh` | 任意 | 经 SSH 装到远程 Ubuntu / 其它 VM |
| `deploy/linux/install.sh` | WSL / Linux 内 | `/opt/taskrunner` + systemd |

更细的单元 / nginx / 排错：[deploy-ubuntu.md](deploy-ubuntu.md)。

## 六、常见卡点

1. **Windows 连不上 `127.0.0.1:5432`**  
   `wsl -d Ubuntu -- systemctl status postgresql`；`listen_addresses` / `pg_hba`；`wsl --shutdown` 后重开再测。

2. **`systemctl` 不存在或一直 starting**  
   未开 systemd：检查 `/etc/wsl.conf` 的 `[boot] systemd=true`，然后 `wsl --shutdown`。

3. **`deploy-wsl` 提示 CHANGE_ME / 服务不起**  
   改 `/etc/default/taskrunner`（连接串）与 `taskrunner-api`（密钥），不要改包内 appsettings。

4. **两个 Hangfire Server 抢活**  
   Windows Combined 与 WSL `taskrunner-worker` 不要同时连同一库。

5. **发行版名字不对**  
   `wsl -l -v` 看 NAME，传给 `deploy-wsl.ps1 -Distro ...`。
