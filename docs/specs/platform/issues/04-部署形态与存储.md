# 04 把部署形态与存储基线钉成发布验证清单

- 状态：`done`（2026-10-26；v3.0.0 本地 PostgreSQL 运行时验证 + CD 产物矩阵通过）
- Blocked by：无
- 缝：运行时验证（发布验证阶段人工执行；超出双缝，开发规格明确归属发布流程）

## 交付什么

部署侧承诺的验收基线：两种宿主角色分化、迁移自动建表、双 schema、
成功作业过期清理、发布产物矩阵。对应开发规格 User Stories 13–15。

## 现状（已随 v3.0.0 交付并验证）

- 宿主装配按角色分化：Api 注册入队与监控读侧，Worker 注册执行侧；开发单进程双角色。
- PostgreSQL 单库：EF 迁移自动建业务表；Hangfire 自建独立 schema。
- 存储 fail-fast：连接标识校验失败即启动失败。
- 成功作业按共享配置的保留时长过期清理。
- CD：tag 触发，Api/Worker × win-x64/linux-x64 四产物挂 Release；CI 带 NuGet 缓存与 concurrency 取消。

## 验收条件

- [x] 迁移验证：全新空库启动即建 `TaskConfigs` 与 Hangfire schema，零手工 SQL
- [x] 作业注册验证：启动后周期作业出现且按生效 Cron 排期
- [x] Dashboard / REST / Scalar 三入口可达（鉴权生效，见票 03）
- [x] Release 产物：四平台单文件包存在、体积非零、可直接启动
- [x] 存储配置错误时启动失败（fail-fast 而非静默降级）

## 不在本票范围

- 跨实例部署的存储级调优、非 PostgreSQL 提供程序（开发规格 Out of Scope）；
- 把运行时验证搬进 CI（人工发布验证是开发规格写明的分工）。
