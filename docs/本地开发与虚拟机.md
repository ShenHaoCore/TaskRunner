# 本地开发 + Ubuntu 虚拟机说明书

面向：家里 / 公司 **Windows**（或 Mac）上写代码；**PostgreSQL 装在本机的 Ubuntu 虚拟机里**；需要时再把同一份程序包装进这台 VM，用 systemd 跑「类生产」。

核心原则：**仓库和发布包永远一份；宿主机用 User Secrets，虚拟机用 `/etc/default/taskrunner`，都不要改包内 `appsettings.json`。**

```text
Windows / Mac 宿主机                      Ubuntu 虚拟机（同一台电脑上）
─────────────────────                     ────────────────────────────
dotnet run Api (Combined)  ──TCP 5432──►  PostgreSQL（唯一数据库）
User Secrets → Host=虚拟机IP              库内：业务表 + hangfire schema
publish-linux → tar.gz     ──scp/ssh──►  systemd Api + Worker
                                          /etc/default/taskrunner
                                          Host=127.0.0.1（连本机 PG）
```

开发与 VM 里的生产形态**共用同一套 PostgreSQL**（都在虚拟机里）。区别只是：宿主机跑的是 `dotnet run`，VM 里跑的是安装后的 Api/Worker 服务。

---

## 一、Ubuntu 虚拟机：先把库和网络弄好

在 VirtualBox / Hyper-V / VMware / UTM / Parallels 里准备 Ubuntu 22.04 或 24.04。

### 1. 网络（宿主机必须能访问 VM 的 22 和 5432）

| 模式 | 宿主机怎么连 |
|------|----------------|
| 桥接 | `虚拟机局域网IP`（如 `192.168.1.20`） |
| 仅主机 (Host-Only) | 如 `192.168.56.10` |
| NAT + 端口转发 | 转发 `2222→22`、`15432→5432`，宿主机连 `127.0.0.1` 对应端口 |

先确认 SSH：

```bash
ssh 用户@虚拟机IP
```

### 2. 在 VM 里安装 PostgreSQL

```bash
sudo apt update
sudo apt install -y postgresql
sudo -u postgres createuser -P taskrunner    # 记住这个密码
sudo -u postgres createdb -O taskrunner taskrunner
```

### 3. 允许宿主机连进来（关键）

默认 PostgreSQL 往往只听 `127.0.0.1`，Windows 上的 `dotnet run` 会连不上。

```bash
# 看配置文件位置（版本号按实际，如 16）
sudo -u postgres psql -c "SHOW config_file;"
sudo -u postgres psql -c "SHOW hba_file;"
```

编辑 `postgresql.conf`：

```conf
listen_addresses = '*'
```

编辑 `pg_hba.conf`，增加一行（按你的虚拟网段改；仅主机常见 `192.168.56.0/24`）：

```text
host    taskrunner    taskrunner    192.168.56.0/24    scram-sha-256
```

重启：

```bash
sudo systemctl restart postgresql
```

在 **Windows 宿主机** 上测（PowerShell）：

```powershell
# 若已安装 psql；没有可用其它客户端或先跑起来看连接错误
Test-NetConnection 虚拟机IP -Port 5432
```

### 4. sudo / SSH

后面 `deploy-ubuntu-vm` 会在 VM 里执行 `sudo bash .../install.sh`，需要能交互输入 sudo 密码（脚本带了 `ssh -t`）。

## 二、Windows（或 Mac）开发机：第一次准备

### 1. 工具

| 工具 | 说明 |
|------|------|
| .NET 9 SDK | `dotnet --version` 为 9.x |
| Git | clone / pull |
| OpenSSH 客户端 | Windows：可选功能里安装；Mac 自带。用于打包装进 VM |

**不需要**在 Windows 上再装一份 PostgreSQL，也**不必**为了本项目再开 Docker PG（库已经在 VM 里）。

### 2. 拉代码

```bash
git clone <仓库地址>
cd TaskRunner
git switch develop
```

### 3. 把连接串指到「虚拟机里的 PG」

**不要改**仓库里的 `src/appsettings.json`。

把下面的 `虚拟机IP`、`密码` 换成你的：

```powershell
# Windows
./scripts/setup-dev-secrets.ps1 -ConnectionString "Host=192.168.56.10;Port=5432;Database=taskrunner;Username=taskrunner;Password=你的密码;"
```

```bash
# Mac
./scripts/setup-dev-secrets.sh 'Host=192.168.56.10;Port=5432;Database=taskrunner;Username=taskrunner;Password=你的密码;'
```

NAT 端口转发时，可能是：

```powershell
./scripts/setup-dev-secrets.ps1 -ConnectionString "Host=127.0.0.1;Port=15432;Database=taskrunner;Username=taskrunner;Password=你的密码;"
```

家里电脑、公司电脑各执行一次（User Secrets 不跟电脑走）。虚拟机 IP 若变了，再跑一遍即可。

### 4. 跑起来

先开着 Ubuntu 虚拟机（PG 在跑），再在宿主机：

```bash
dotnet test
dotnet run --project src/TaskRunner.Api
```

开发环境 Api 是 **Combined**（入队 + 执行），一般**不用**再开 Worker。数据写进 **VM 里那同一个库**。

| 入口 | 地址（在宿主机浏览器） |
|------|------------------------|
| 首页 | http://localhost:5088 |
| Dashboard | http://localhost:5088/taskrunner |
| Scalar | http://localhost:5088/scalar |
| 任务 API | http://localhost:5088/api/tasks |

Development 下 Dashboard / 写操作免管理员密钥。

## 三、把程序也装进虚拟机（类生产）

此时库已经在 VM 里；这一步是让 **Api + Worker 以 systemd 跑在 VM 里**（和宿主机 `dotnet run` 不要同时抢同一套 Hangfire Server，见下方注意）。

### Windows 宿主机

```powershell
cd E:\Repos\TaskRunner
./scripts/publish-linux.ps1
./scripts/deploy-ubuntu-vm.ps1 -Target 用户@虚拟机IP
```

### Mac 宿主机

```bash
./scripts/publish-linux.sh
./scripts/deploy-ubuntu-vm.sh 用户@虚拟机IP
```

### 第一次：只改 VM 的 env

```bash
ssh 用户@虚拟机IP
sudo nano /etc/default/taskrunner
```

```bash
# 程序与 PG 都在同一台 VM 内 → 用 127.0.0.1
ConnectionStrings__Default='Host=127.0.0.1;Port=5432;Database=taskrunner;Username=taskrunner;Password=你的密码'
Hangfire__AdminApiKey='自己想一个足够长的密钥'
```

**不要**改 `/opt/taskrunner/**/appsettings.json`。

```bash
sudo systemctl start taskrunner-api taskrunner-worker
systemctl status taskrunner-api taskrunner-worker
curl -H "X-TaskRunner-Admin: 你的密钥" http://127.0.0.1:5088/api/tasks
```

### 注意：开发 Combined 与 VM Worker 不要同时开

两边连的是**同一个库**。若宿主机 `dotnet run`（Combined，自带 Server）与 VM 里 `taskrunner-worker` 同时跑，会出现两个 Hangfire Server 抢队列（一般能跑，但排错费劲）。建议：

- **日常改代码**：只开宿主机 `dotnet run`，VM 上 `sudo systemctl stop taskrunner-api taskrunner-worker`
- **验 Linux 部署**：停掉宿主机 Api，再 `systemctl start` VM 上的服务

## 四、日常怎么用

| 你想做的事 | 在哪 | 怎么做 |
|------------|------|--------|
| 改代码、调试 | 宿主机 | 开着 VM（PG），`dotnet run --project src/TaskRunner.Api` |
| 虚拟机 IP / 密码变了 | 宿主机 | 再跑 `setup-dev-secrets`，连接串写成新 IP |
| 验 systemd 部署 | 宿主机打包 → VM | `publish-linux` + `deploy-ubuntu-vm`；停掉本机 Combined |
| 升级 VM 里的程序 | 同上 | 重跑打包安装；`/etc/default/taskrunner` 会保留 |
| 只改 VM 服务密钥 | 只上 VM | 编辑 `/etc/default/taskrunner`，`systemctl restart ...` |

家里、公司若各有一台 VM，就是两套 PG + 两套 env，互不相干。

## 五、脚本速查

| 脚本 | 谁用 | 干什么 |
|------|------|--------|
| `setup-dev-secrets.ps1` / `.sh` | 宿主机 | 写入 User Secrets（**Host 填虚拟机 IP**） |
| `publish-linux.ps1` / `.sh` | 宿主机 | 打 linux-x64 包 |
| `deploy-ubuntu-vm.ps1` / `.sh` | 宿主机 | 上传并在 VM 执行 install |
| `deploy/linux/install.sh` | VM 内 | 装到 `/opt/taskrunner` + systemd |

更细的 systemd / nginx / 排错：[deploy-ubuntu.md](deploy-ubuntu.md)。

## 六、常见卡点

1. **宿主机 `dotnet run` 连不上库**  
   - 虚拟机是否开机、`postgresql` 是否 `active`  
   - Secrets 里的 Host 是不是虚拟机 IP（不是 `127.0.0.1`，除非做了端口转发）  
   - `listen_addresses` / `pg_hba.conf` 是否允许宿主机网段  
   - `Test-NetConnection 虚拟机IP -Port 5432` 是否 TcpTestSucceeded

2. **VM 里服务正常，宿主机浏览器打不开 5088**  
   那是 **Api 跑在哪**：`dotnet run` 时 Api 在宿主机 `localhost:5088`；systemd 时 Api 在 VM 里（默认只绑 VM 的 `127.0.0.1`）。从宿主机访问 VM 上的 Api，需在 `/etc/default/taskrunner` 设 `ASPNETCORE_URLS='http://0.0.0.0:5088'` 后重启（仅信任的虚拟网）。

3. **`systemctl start` 失败，日志有 CHANGE_ME**  
   只改 `/etc/default/taskrunner`，不要改包内 appsettings。

4. **`deploy-ubuntu-vm` 找不到 scp/ssh**  
   Windows 安装「OpenSSH 客户端」。

5. **脚本默认的 15432 Docker 连接串**  
   `setup-dev-secrets` 若不传参数，会写成 README 里的 Docker 示例。你这种「PG 在 VM」的用法**必须带 `-ConnectionString` / 参数**，指到虚拟机 IP。
